# display-agent

Мост между render-rs и USB-дисплеем (MCU). Подписывается на WebSocket рендера
в raw-формате (сервер сам даунскейлит и конвертирует пиксели под матрицу) и
пишет кадры в sink фреймированным бинарным протоколом.

Устройство остаётся тупым: рисует кадры как есть и шлёт коды кнопок обратно.

## Запуск

```bash
# стрим в файл (валидация без железа)
cargo run -- stream \
  --url ws://localhost:8092/api/renders/1/ws \
  --format rgb565 --width 256 --height 144 --fps 10 \
  --out file:display-stream.bin

# проверка записанного потока: пейсинг, целостность, пропуски seq
cargo run -- inspect display-stream.bin

# вытащить кадр N как PNG (посмотреть глазами)
cargo run -- inspect display-stream.bin --dump 50:frame.png
```

Sink `serial:/dev/ttyACM0` — следующий шаг (протокол уже готов).

## Протокол устройства (little-endian)

Пакет: `0xA5 | type u8 | len u32 | ts_ms u64 | body[len]`

- `type 0x01` — кадр (host → device). Body — кадр WS рендера без изменений:
  `"FR" | fmt u8 (0=rgb565, 1=rgb888) | flags u8 | w u16 | h u16 | seq u32 | pixels`
- `type 0x02` — ввод (device → host): `key u8 | state u8` (1=down, 0=up).
  Агент замапит коды кнопок в события рендера (`ArrowUp`/`Enter`/...).

Кадр 256×144 rgb565 = 73 728 байт (~720 KB/s при 10 fps — влезает в
full-speed USB CDC).

**Важно про маленькие матрицы:** не даунскейлить большой рендер, а создать
рендер сразу в родном разрешении дисплея и подписаться без `w/h`:

```bash
curl -X POST localhost:8090/api/renders -H 'Content-Type: application/json' \
  -d '{"url":"http://localhost:5173/","width":256,"height":144,"fps":10}'
```

Даунскейл 640×480 → 256×144 (нецелый коэффициент) уничтожает пиксельный
шрифт — от текста остаются точки. При рендере в родном размере страница
верстается под матрицу и текст остаётся читаемым.

## Параметры raw-подписки render-rs

`GET /api/renders/{id}/ws?format=rgb565&w=256&h=144&fps=10`

- `format`: `png` (по умолчанию, для браузера) | `rgb565` | `rgb888`
- `w`,`h`: серверный даунскейл (Nearest); без них — родной размер рендера
- `fps`: темп конкретного подписчика (1–60)

Кадры конвертируются на сервере только при изменении картинки; неизменный кадр
переотправляется из кеша — постоянный fps без лишнего CPU.
